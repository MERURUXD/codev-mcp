# 支持能力与限制清单

本清单说明工具、独立命令行入口及使用边界。真实后端需要 Windows、CODE V 10.2 与可用许可证；实验性版本不保证所有镜头和故障路径都能完成。模拟后端只用于协议和流程演示，其数值不用于光学结论。

## 1. 工具能力

| 工具 | 能力 |
| --- | --- |
| `get_status` | 后端类型、CODE V 版本、会话与镜头状态、当前任务、能力清单 |
| `open_lens` | 打开 `.len` 工作副本，返回完整镜头数据 |
| `create_lens` | 仅在空会话中按类型化规格新建单变焦普通球面镜头；可选 `image_solve="pim"` 给最后一个普通面厚度加近轴像面求解（请求厚度只是初值）；完整回读、保存重开后发布 revision 0 |
| `get_lens` | 表面编号/角色/拦光面、半径与厚度（含无穷标记）、玻璃名与目录、单位、系统孔径原生类型和值、显式通光孔径/遮拦、有效最大孔径、视场（含渐晕因子 `vux/vlx/vuy/vly`）、波长、变焦位置 |
| `update_lens` | 表面半径/厚度/玻璃、视场 X/Y 角与权重、视场渐晕因子 `vux/vlx/vuy/vly`（-0.99～0.99）、波长值/权重/参考波长；单变焦镜头现有系统孔径值及单一居中圆形显式通光孔径半径；每批一个恢复点；回读校验；整批要么全生效要么全回滚；平面（无限半径）面可以直接设为有限半径（仅半径编辑可改变无穷标志，其余编辑改变它仍整批回滚），厚度仍不能在无穷与有限之间改。另可用 `field_set` 整体替换单变焦角视场的集合（个数、角度、权重、渐晕因子，独立事务，不与 `edits` 同批，见[视场集合](field-set-and-seq-import.md)） |
| `edit_lens_structure` | 仅对当前服务新建的简单球面镜头批量插入／删除普通面和设置光阑；逐步编号映射与完整回读核对，失败整批恢复 |
| `run_analysis` | 一阶参数、点列图、衍射正弦 MTF、当前保存焦面的 WAV RMS／Strehl；`native_plot` 由 CODE V 自己绘制并导出 PNG（五类绘图） |
| `get_analysis` | 任务状态、结构化数值、图像（作为 MCP 图像内容返回，同时保留结果文件）；原生绘图另带 `.PLT` 路径与大小 |
| `cancel_analysis` | 请求取消，并区分“已请求”与“已确认停止”；对异步任务（点列图、原生绘图）有效，原生绘图还会关闭 CODE V 已打开的绘图文件 |
| `save_lens_as` | 另存为新文件，拒绝覆盖源文件与已存在文件 |
| `close_session` | 释放本服务创建的会话并清理本次会话的进程 |

独立扫描 CLI 的 `--config` 可在已确认固定焦面的单变焦镜头上选取一阶、点列、MTF、WAV，产生逐样本指标、条件绑定曲线和逐项要求状态，并显式另存候选后独立重开复算。它不新增公共 MCP 工具、不自动改焦或接受候选。

统一约定：所有结果带 `source`（`codev` 或 `simulated`）；所有失败返回结构化错误（`parameter`、`not_ready`、`computation_failed`、`session_invalid`、`unsupported`、`not_found`、`internal`）。

模拟后端使用自建合成模型，`dbgauss` 文件名选择分支也返回合成数据。一阶常数是测试数据；模拟后端不解析真实 `.len`，不证明物理性能。

### 初始／最终镜头对比流程

公共工具之外提供命令行编排入口 `python -m codev_mcp.compare`，复用上述工具生成初始／最终镜头分析对比包，不增加 COM 命令入口。支持范围、默认严格兼容检查、视场权重差异选项和失败规则见 [对比流程](comparison-workflow.md)。模拟流程仅验证协议与产物组织，不解析真实镜头。

对比入口可显式选择分析种类、视场、MTF 频率和点列网格配置，`python -m codev_mcp.batch` 生成批量逐对报告。批量只汇总同请求、同实际设置的完整数值结果，不给跨条件排名。显式多变焦编排仅覆盖一阶、点列、数值 MTF；WAV 和原生图仍限单变焦。说明见[双镜头流程](comparison-workflow.md)和[批量流程](batch-workflow.md)。

独立的[本机玻璃目录查询 CLI](glass-catalog.md)通过 CODE V 原生 `GLD` 只读查询预装目录、精确玻璃名及指定波长的列表折射率，不增加 MCP 工具，不改用户镜头。双镜头对比记录运行耗时与 COM 调用数，并支持显式 `--max-analyses-per-session` 有界复用；默认逐项独立会话。详见[性能流程](performance-workflow.md)。

独立的[固定网格参数扫描 CLI](parameter-scan.md)修改单变焦镜头的现有半径或厚度，每个值从同一基线快照开启独立会话，复用 `update_lens` 事务与一阶分析；失败样本独立记录，不隐式寻优，不增加 MCP 工具。

受控 AUT 的类型化规格、约束与分阶段行为见[多变量约束与分阶段 AUT](#多变量约束与分阶段-aut)。

### 设计规格评价与判定

对比入口支持单镜头模式 `--lens` 与 `--spec`：[设计规格](design/design-spec.md)决定分析种类、结构化 MTF 频率与点列网格，包内另存原生 `LIS` 文本、规格副本、图与数据对应清单，并按规格逐项判定写入 `evaluation.json`。判定覆盖系统定义（孔径、视场、波长、玻璃目录）、一阶参数（`OAL` 不含像距）、MTF、点列、WAV、FIE 参考波长畸变表的最大绝对值、玻璃与空气的中心／边缘厚度，以及显式选用的 Maréchal 与艾里斑预设。边缘厚度与艾里斑直径是服务按 CODE V 数据计算的值，分别标记；打印精度跨越阈值、缺数据、模拟来源或待补阈值一律为 unknown。不新增 MCP 工具、不发送新的 CODE V 命令、不修改镜头；原生 MTF 图仍固定 `MFR 100; IFR 10`。

### 相近玻璃候选

独立只读 CLI `python -m codev_mcp.glass_near` 以参考玻璃（`名称_目录`）或 nd／νd 为基准，从调用方指定的预装目录 `GLI` 列表中按 √((Δnd/0.01)²+(Δνd/1)²) 排序列出候选，νd 由打印折射率计算并给出打印精度区间。不预设目录、不替换玻璃。说明见[玻璃目录查询](glass-catalog.md#相近玻璃候选)。

### 起点缩放

独立 CLI `python -m codev_mcp.scale` 经公共 MCP 工具，把单变焦、只有 `PIM` 求解、无拾取、无特殊面的角视场镜头按目标 EFL 或系数整体缩放：有限半径、非求解厚度、有限物距、EPD 与唯一居中圆形通光孔径在一次 `update_lens` 事务中乘以同一系数；`PIM` 像距交由 CODE V 重新求解并逐项报告；另存后在独立会话重开复算，EFL 相对偏差超过 1e-9 即失败且不写输出。每次运行留下[执行记录](design/execution-record.md)，列出实际发送的等效命令。

### 多变量约束与分阶段 AUT

[受控 AUT](controlled-aut.md)使用类型化规格：多个阶段依次运行，每阶段可设现有球面半径／厚度变量（可带上下界）、白名单具体约束（`EFL`、`EFY`、`OAL`、`IMD`、`DIY`、`CT`、`ET`）、通用厚度约束（`MXT`、`MNT`、`MNE`、`MNA`、`MAE`）、误差函数参数（`MXC`、`MNC`、`TAR`、`IMP`、`DEL`、`WTA`）和视场／波长权重修改。允许保留 `PIM` 及不控制请求变量的求解／拾取并逐项列出。AUT 输出经 `OUT` 重定向到服务文件后解析，具体约束按最终表逐条判定，通用约束由服务按厚度判定复核并列出 CODE V 冻结厚度警告；运行后恢复原生变量控制码。每阶段保存并核对中间候选，后续阶段失败时保留前序候选；约束未满足的候选可接受但明确标出。阶段前可类型化修改视场角、权重与渐晕因子；`field_ramp` 展开为逐步从上一候选继续的阶段，仍只能显式接受最终候选。变量起始值可以在界上或界外，阶段记录注明；渐晕因子不是 AUT 变量。起始为平面（无限半径）的面可以作为 `radius` 变量，平面起点不带半径界；变量记录带 `before_infinite`／`after_infinite`。

### 类型化编辑、可读序列导出与设计记录

- `python -m codev_mcp.edit`：按 `lens_edits` 文件（公共 `ParameterEdit` 记录，1～100 条）对单变焦镜头副本发一次 `update_lens` 事务，例如换玻璃；回读、另存、独立会话重开复算，不写输入。执行记录里的等价命令按后端格式重建。
- `python -m codev_mcp.export_seq`：只发送 `RES`／`WRL`，把镜头导出为新的可读 `.seq`，拒绝覆盖。AUT 后的镜头会带 `DER VAL` 导数增量行。
- `python -m codev_mcp.seq_import`：把 `.seq` 按命令白名单解析为类型化请求（`create_lens` 含 `PIM`、`update_lens` 视场集合与波长编辑），由服务构造命令、不执行序列和 `IN`；白名单外的行整份拒绝并逐行列出，元数据与变量标记列为“未导入”；导入后逐项核对读回值和 `LIS`，另存后独立会话重开复核，可与参考 `.len` 逐项比对。
- `python -m codev_mcp.schemes`：从同一基线批量运行多个方案（类型化修改：换玻璃、渐晕或视场集合、可各带自己的 AUT 规格）→ 分阶段 AUT → 候选，默认串行，`--jobs N`（1～8）让 N 个方案在各自的工作进程和会话中同时运行（会话启动由机器级互斥量排队，共享的 `cvcomsvr.exe` 不被单个会话结束），单个方案失败只记录并继续（留下无法确认的进程则不再启动新方案）；汇总误差函数、WAV、一阶参数和可选的规格判定，列出可比与不可比的量（渐晕、视场权重、波长权重或误差函数设置不同时误差函数与 WAV 不可直接比较，分组说明），可用 `--screen-cycles N --finalists K` 先按误差函数可比组粗筛，再从原始基线独立完整运行每组最多 K 个入围方案；粗筛保留阶段／约束与 WAV 诊断，最终推荐只用完整阶段结果。清理判断读取结构化状态，诊断超时且最终确认无残留时继续后续方案。只推荐、不接受候选。见[多方案比较](scheme-comparison.md)。
- `python -m codev_mcp.deliver`：把评价包与 AUT 运行整理成报告素材：初始／最终成对图（`init-*`、`final-*`，含原生 `.PLT`）、`LIS`、WAV 原文、优化宏（原样命令块与由记录裁剪的等效手写宏；`--setup` 可把换玻璃、缩放、`.seq` 导入的等效命令放在前面）、AUT 原始输出与摘要、资料索引；只复制、核对哈希，不重算、不发命令，拒绝覆盖；初始镜头无法完整追迹时只给实际生成的图并逐项列出原因。见[交付整理](deliverable.md)。
- `python -m codev_mcp.fieldset`：由最大视场角和相对视场计算角度，默认按像高（tan）归一化并注明口径，输出可直接用作 `update_lens` 的 `field_set`；只计算，不连接 CODE V。
- `python -m codev_mcp.edit` 的编辑文件可改用 `field_set`（与 `edits` 二选一）。详见[视场集合、按像高归一化与 `.seq` 导入](field-set-and-seq-import.md)。
- `python -m codev_mcp.walkthrough`：读取各 CLI 的[执行记录](design/execution-record.md)和设计规格，生成中文设计记录。内容包括目标与指标、素材、按顺序的步骤和可复现命令、出图清单、实测数据与判定、注意事项。只渲染记录中的数值，缺失写“缺失”，不写报告正文，不复制图片，拒绝覆盖。

## 2. 当前明确不支持

- 公共 MCP 工具中的自动优化、公差与灵敏度分析。AUT 仅通过独立的[受控候选命令行](controlled-aut.md)按类型化规格运行；不在 `run_analysis` 中修改镜头。AUT 不支持多变焦、玻璃变量、非球面、像面离焦变量、`IMC`／`TT`／光线约束、用户自定义误差函数
- 任意现有镜头的增删表面、修改表面类型或特殊面型；结构编辑仅开放上述受限新建镜头
- 任意命令或宏执行：服务只发送自己构造的、参数经过白名单校验的命令
- 远程访问：只提供本机 stdio
- 控制用户已打开的 CODE V 图形界面（服务只创建并使用自己的无界面会话）
- 无焦系统的 MTF（返回 `unsupported`）
- 几何 MTF（首版只做衍射正弦 MTF）
- 系统孔径类型切换；自动孔径转显式孔径；`CA NO` 下保留但不生效的显式圆孔径编辑；遮拦、非圆形、偏心、旋转、OR/复合及多变焦孔径编辑。NA/NAO 写入保守限制为小于 1，尽管高折射率介质中 ≥1 可能有意义。旧名称 `semi_aperture`、`clear_aperture` 语义不明确，继续只读
- 一次任务计算多个视场的点列图（每次一个视场）

## 3. 限制与注意事项

1. **长会话稳定性**：不要把单个 CODE V 会话当作无限期运行的服务。调用开销随镜头与采样设置变化；长时间连续操作宜分段进行，必要时重新建立会话。`--max-analyses-per-session` 是有界编排选项，不是 CODE V 的固定安全调用阈值。
2. **一次一个分析**：分析运行期间拒绝 `open_lens`、`get_lens`、`update_lens`、`save_lens_as` 与第二次 `run_analysis`。
3. **异步任务是点列图与原生绘图**：两者都以 `AsyncCommand` 异步提交，需要轮询 `get_analysis`，运行中可以 `cancel_analysis`。一阶参数、MTF 与 WAV 在 `run_analysis` 内部同步执行完毕才返回，运行期间无法取消；此时其它调用只会在客户端队列里等待，超过单次调用超时（默认 300 秒，`--timeout` 可调）后客户端会终止工作进程，需要重新启动服务建立会话。预估耗时长的分析请先用 `--timeout` 放宽上限，或分批提交。
4. **多变焦镜头**：修改必须给出 `zoom_position`；若该参数本身没有被变焦，服务改共享值并在 `warnings` 里说明。
5. **求解与拾取**：由求解或拾取控制的参数会被拒绝；求解探测本身失败时编辑仍会尝试，并在 `warnings` 里说明，回读校验兜底。即使 CODE V 静默忽略某次修改，回读校验也会发现并整批回滚。
6. **无穷值**：半径 ≥1e17、厚度 ≥1e10 视为无穷；CODE V 的无穷值表示可为 `0.1E+19` 与约 `9.9e11`。
7. **数值精度**：一阶参数来自字符串求值，约 16 位有效数字；后/前焦距与近轴像高来自列表打印，只有打印精度，已单独标注。
8. **点列图口径**：原生 SPO 报的是直径，服务换算为半径并置 `size_is_radius=true`；`statistics_sample_count` 是原生统计用的光线数，`plot_sample_count` 是绘图网格的射线数；绘制坐标用 RAYTRA 追踪（必须开启孔径检查，否则被遮拦射线会返回无效坐标）。网格发射点做真实光线瞄准：每个波长用 17 条 `RAYRSI` 光线（相对光瞳，读 `(X S1)`、`(Y S1)`、`(Z S1)`，减去 Z×物方方向正切换算到第一切平面）拟合三次多项式，再用 `RAYTRA` 追踪网格；相对光瞳按该视场的渐晕因子缩放，与原生 SPO 追迹同一光瞳。映射与标定光线偏差超过光瞳半径 0.5% 时给出警告，被孔径拦掉的绘图网格光线会被列出并不绘制；标定光线不足 10 条时点列任务失败。绘图以网格质心为中心，灰圈为原生 100% 半径，绿圈为服务计算的艾里斑半径 1.22λF/#（参考波长与无限共轭 F/#，有限物距不画，不是 CODE V 结果）。绘图网格与原生 SPO 的采样不同，不能用绘图网格 RMS 代替原生统计。
9. **输出截断**：输出填满文本缓冲时任务标记 `output_truncated=true` 并在 warnings 里说明；缺统计时按失败处理，不给出部分结果。
10. **会话失效**：回滚失败或停止未被确认时标记会话失效，之后拒绝写操作。

11. **孔径读取与编辑边界**：`aperture.kind` 保留原生 `epd`、`fno`、`na`、`nao`，`value` 是该类型在实际变焦位置的值；只有 EPD 使用镜头长度单位。`derived_epd` 是单独标记的推导值。表面 `semi_aperture` 来自 `GetMaxAperture`，表示 CODE V 计算的有效最大半孔径，不等于显式 `CIR` 定义。显式定义保存在 `surfaces[].apertures`，半径使用镜头长度单位；多变焦表面值读取 `LIS` 的 `ZOOM DATA`，读取不完整时 `aperture_data_complete=false` 并禁止写入。孔径编辑只允许单变焦、保持系统孔径类型只改数值，或在 CA 使用用户定义孔径时修改表面唯一的居中圆形通光孔径半径；没有显式定义、`CA NO`、遮拦或任何复杂组合都会在写入前拒绝。

12. **镜头可信状态与检查点**：`update_lens` 只有在整批修改完成回读核对、并把工作副本写入独立检查点（保存 → 重新载入 → 逐项比对）之后才报告成功。检查点位于 `<工作目录>/checkpoints/<后端实例 UUID>/<镜头 UUID>/revision-00NNNN.len`，成功版本由同目录的 `current.json` 指向；版本文件从不覆盖。检查点格式由 [`CHECKPOINT_FORMAT_VERSION`](../src/codev_mcp/checkpoints.py) 定义；格式 6 纳入原生系统孔径类型、各变焦值、CA 使用模式、逐变焦表面孔径、原生孔径命令、`LIS` 中的求解／拾取命令、`CCY/THC/GLC` 变量控制码，以及逐视场、逐变焦的渐晕因子 `VUX/VLX/VUY/VLY`；缺失关系区或变量控制列会拒绝快照，变焦位置 1 的渐晕因子与 `LIS` 规格区打印值（五位小数；未打印的行按全零）不符时也拒绝快照，以防未识别的数据库项回显上一个结果。版本 1～5 拒绝自动恢复并提示重新打开源镜头，旧文件不会被改写。渐晕因子可经 `update_lens` 按视场、按变焦位置写入（`VUX/VLX/VUY/VLY Fn`，限 -0.99～0.99），与其它参数同样回读、与 `LIS` 交叉核对并写入检查点；修改其它参数时若渐晕因子随之变化，整批回滚。快照仍不完整覆盖特殊面型、偏心、涂层等属性，因此结构写入只允许本服务新建的简单球面镜头。引擎退出后，下一次镜头操作会重建会话，并从 `current.json` 指向的版本恢复并核对；恢复无法确认时会话标记失效。

13. **求解联动**：整批修改要求“只有被请求的参数发生变化”，但 CODE V 会按求解重新推导求解控制的参数（例如由 `PIM` 控制的像面间隔随前面间隔变化）。这类联动只有在服务确实探测到该参数由求解控制时才被接受，并在 `warnings` 里逐项列出；没有求解解释的变化仍然整批回滚。
14. **进程清理范围**：只清理本服务记录过的 CODE V 进程；用户自己启动的会话不受影响。
15. **引擎崩溃的随机性**：CODE V 无界面引擎会在启动时随机崩溃（`0x40000015` 或 `c0000005`），并停在「应用程序错误」对话框上；此时 COM 服务器仍在，之后的调用会永久阻塞。服务已加入三项防护（详见 `docs/install.md` 6.4）：启动阶段看门狗发现无线程的引擎立即终止它（对话框随之消失，不需要人工点掉）；会话启动最多重试 4 次；运行中的引擎死亡后，下一次调用会丢弃死会话、重建会话，并从最近成功检查点恢复镜头后核对。重建是透明的；正在跑的分析任务会被标记为 `failed`，其 `error` 记录 `session_invalid` 与中断原因，结果文件保留，需要重新提交；历史分析结果会标注其所属镜头与版本（任务上置 `history_only=true`，`get_status.details` 给出 `analysis_lens_id` 与 `analysis_history_only`），保留真实 `source=codev`，不会冒充当前镜头的结果；引擎退出也不会清除已经完成的既有结果。

16. **原生绘图导出**：`run_analysis` 支持 `kind=native_plot`，必须给出 `options.plot_type`（`layout` 对应 `VIE;LAB NO;GO`、`spot` 对应 `SPO;AIR YES;GO`（叠加按实际光线 F 数与参考波长计算的艾里斑圆）、`mtf` 对应 `MTF;MFR 100;IFR 10;GO`、`ray_aberration` 对应 `RIM;GO`、`field_aberration` 对应 `FIE;LSA;GO`）。服务不接受任何输出路径：绘图文件与 PNG 都写在服务结果目录内，文件名由服务生成并带唯一随机成分，绝不覆盖已有文件。首版只支持 PNG 并同时保留 CODE V 写出的原始 `.PLT`；不提供 TIF/RAS 等格式选择，不读取用户已打开的 CODE V 图形界面，也不使用截图或桌面自动化。它忠实绘制镜头启用的全部视场与波长，因此不接受 `field_numbers`、`wavelength_numbers`、`ray_grid`、`frequencies`、`azimuth`、`mtf_type` 等筛选参数（传入即返回 `parameter`）；首版仅支持单变焦镜头，多变焦返回 `unsupported`。轮询收尾顺序固定为 `GetCommandOutput` → `GRA T` → 校验非空 `.PLT` → `GCV PNG` → 校验 PNG；其中 `Wait()` 报完成但 `IsExecutingCommand()` 仍为真时不会提前收尾。校验 PNG 时会遍历整个 chunk 列表并逐个核对 CRC、要求以空的 `IEND` 结尾且其后没有多余数据，并把像素数据作为完整的 zlib 流解压验证，因此“签名与 IHDR 合法但文件被截短”的图片不会被当成有效图像。命令错误、输出为空、命令输出被文本缓冲截断、`.PLT` 缺失或为空、转换失败、PNG 不完整或无法解码一律返回 `computation_failed`（截断时已写出的文件保留供诊断，但不算完整结果）；`GRA T` 无法确认时标记会话失效。轮询本身失败（`Wait`、`IsExecutingCommand` 或 `GetCommandOutput` 抛错）时会先 `StopCommand` 并确认停止、再 `GRA T` 恢复图形输出，然后才报告失败；停止或恢复无法确认时会话失效，任务仍然结束在最终状态而不会一直停在 `RUNNING`。文件访问错误（例如转换后的 PNG 无法读回）同样转换成结构化 `computation_failed` 并结束任务，已经写出的文件保留在结果目录里。CODE V 会把绘图文件的整个 filespec 截断到 80 个字符，并且只在截断后仍有空间时追加 `.PLT`，因此服务按结果目录剩余空间限制文件名长度，空间不足时直接报错而不是生成会被截断的名字；若 CODE V 仍然写出了没有扩展名的绘图文件，服务会在转换前为其补上 `.PLT`（仅在结果目录内，且不覆盖已有文件）。

17. **WAV 波前分析**：`kind=wavefront` 仅支持单变焦、全部视场和波长，固定 `NRD=20`，显式运行 `NOM` 当前保存焦面，不执行会修改像面厚度的 `RFO`。逐视场和综合 RMS、Strehl、实际光线数均来自 CODE V 原生文本，RMS 单位为 waves；原生 X/Y 视场角须与镜头按行匹配。后端在 WAV 前后比较可验证的镜头快照；发现变化或回读无法确认时任务失败、会话失效并拒绝后续写入。Strehl 是 CODE V 打印的近似值，大 RMS 时可能为 0。镜头参考波长与多波长 RMS 等效波长不是同一字段；原生文本不提供后者，因此结果留空，不以参考波长代替。最佳单独／共同焦面及离焦扫描尚未实现。WAV 同步执行，不可中途取消。大视场的 `rays_traced` 少于轴上，是固定的出瞳网格有一部分被光阑面和默认孔径挡掉，不是追迹失败；逐视场 RMS 是通过孔径那部分光瞳上的值，综合 RMS 按各视场光线数加权，所以光线数明显不同的方案不能直接按 RMS 比较。`compare` 与 `schemes` 的报告并列接受光瞳比，超过 3 个百分点标“光瞳不同”，并列不按光线数加权的综合 RMS；公共工具 `run_analysis` 的结果字段不变。AUT 的优化光线网格不受孔径影响、不会丢光线，评价的光瞳与 WAV 不同。

`FAP` 不在受控 AUT 规格白名单。它会重写渐晕并允许归一化光瞳尺度变化；WAV 光线数接近轴上不能证明光瞳尺寸保持或 AUT/WAV 完全对齐。

18. **安装方式与命令行工作目录**：MCP 服务用 `--working-directory` 指定工作目录，wheel 安装也可使用。独立命令行工具的引擎工作目录由包的安装位置推出，不受 `--output-dir` 影响，因此这些工具按[安装说明](install.md)在仓库根目录可编辑安装后使用。一个工作目录同一时间只供一个会话使用：会话从启动到停止独占该目录（锁文件 `codev-mcp-session.lock`，持有进程退出时由操作系统释放），另一个服务实例在同一目录启动会话时返回 `not_ready`（`details.reason` 为 `working_directory_in_use`，`details.holder` 为持有者 PID），不清理该目录中的恢复文件或进程记录，也不在本次调用内重试；被拒绝的服务不进入失效状态，目录释放后再次调用即可启动会话。多个 MCP 客户端（例如同时打开的多个对话）各自启动服务时，须分别用 `--working-directory` 或 `CODEV_MCP_WORKDIR` 指定不同的工作目录；命令行工具每次运行使用各自的引擎目录，不受影响。
