# 初始／最终镜头分析对比

`python -m codev_mcp.compare` 是公共 MCP 工具的命令行客户端，不新增公共工具。它不执行任意 CODE V 命令、不做优化、不改焦，也不修改输入文件。

## 使用

在仓库根目录设置 `PYTHONPATH=src`，使用装有本项目依赖的 Python：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location).Path 'src'
python -m codev_mcp.compare --initial D:\lenses\initial.len --final D:\lenses\final.len
```

- `--backend com|simulated`：默认 `com`。模拟后端按文件名选取内置样本，**不解析真实 `.len` 内容**，只验证流程。
- `--output-dir`：默认仓库 `.codev-run/comparisons`，每次新建不重名的子目录。
- `--timeout`：单项分析的秒数，默认 300。服务内部单次调用也使用这个上限；协议收尾和会话释放另有等待时间。
- `--allow-field-weight-difference`：默认关闭。显式打开时允许初始／最终视场权重不同，列出差异，只逐视场比较，不计算加权总评分。视场坐标、编号、波长及其权重仍必须一致。
- `--analyses`：逗号分隔选择 `first_order,spot_diagram,mtf,wavefront,native_plot` 的子集；不指定时运行全部分析。
- `--fields`：逗号分隔的视场编号，仅用于一阶、点列与数值 MTF。WAV 和原生图必须使用镜头自身的全视场设置，因此与此选项同时选择会在启动引擎前拒绝。
- `--mtf-frequencies`：逗号分隔、非负、唯一且升序的 cycles/mm 频率，默认 `0,10,...,100`；`--spot-grid` 默认为 7。
- `--zoom-positions`：逗号分隔的变焦位置。指定后默认只运行一阶、点列、数值 MTF；显式包含 WAV 或原生图会被拒绝。每项结果和表格标明位置；其余位置也在分析前后读取并核对公共光学状态。
- `--max-analyses-per-session`：默认 1，即逐项独立会话；显式给 2～8 时，同一镜头的连续分析有界复用会话。单变焦的全部五类分析均支持，包括 WAV、五类原生图和 `--spec` 完整评价；多变焦仍在启动引擎前拒绝复用。预检和不同镜头之间不复用。性能与安全边界见[性能流程](performance-workflow.md)。

默认流程仍仅支持单变焦镜头；显式使用 `--zoom-positions` 才启用多变焦数值编排。单位必须一致。初始／最终镜头均保留其保存时的焦面、孔径和权重；不自动“对齐”或修改镜头。孔径等其他参数允许不同，在镜头快照和一阶参数中保留，因此对比不自动解释为同条件像质优劣。

例如初始权重为 `1/1/1/1/1`、最终为 `1/1/1.2/1/1.8` 时，须显式使用 `--allow-field-weight-difference`；默认严格模式会拒绝这对镜头。

## 设计规格评价包

同一入口支持单镜头评价和按[设计规格](design/design-spec.md)驱动的评价配置：

```powershell
python -m codev_mcp.compare --lens D:\lenses\design.len --spec docs\design\design-spec-dbgauss.json
python -m codev_mcp.compare --initial initial.len --final final.len --spec my-spec.json
```

- `--lens` 与 `--initial/--final` 二选一。单镜头包写 `report.md`，双镜头仍写 `comparison.md`，其余产物结构相同。
- `--spec` 决定分析种类、结构化 MTF 频率和点列网格，与 `--analyses`、`--fields`、`--mtf-frequencies`、`--spot-grid`、`--zoom-positions` 不能同用；规格评价限单变焦、全部视场。规格在启动引擎前校验，原始字节复制为包内 `design-spec.json` 并记录 SHA-256，结束时复核源文件和副本未变。镜头单位与规格不符、要求引用的视场不存在时，在预检后、任何分析前失败。
- 预检把 `get_lens` 读取时使用的原生 `LIS` 文本原样写为 `<阶段>/preflight/lis.txt`，清单 `inputs.<阶段>.listing` 记录路径、大小和哈希。这是只读导出，不发送额外命令；真实后端缺少该文本时预检失败，模拟后端记录为缺失。
- 清单中的 `figures`：每张图的来源（CODE V 原生或服务按数值重绘）、图片哈希，以及对应的数值快照、原生文本或 `.PLT`，供设计记录引用。原生 MTF 图仍固定 `MFR 100; IFR 10`；结构化 MTF 使用规格频率，两者不宣称采样一致。
- 所有分析结束（包括失败）后，每份镜头按规格判定，写入 `evaluation.json`，并在报告末尾列出逐项判定。运行状态与规格判定分开：分析全部成功、判定为 fail 时退出码仍为 0；分析失败时判定照常生成，缺失项为 unknown。

判定规则、预设出处、畸变与边缘厚度口径见[设计规格格式](design/design-spec.md#规格判定)。

## 分析与可追溯性

对每份镜头串行执行一阶参数、每个视场的点列图、全视场衍射 MTF，以及 layout、spot、mtf、ray_aberration、field_aberration 五类原生图。点列图网格为 7；结构化 MTF 频率为 0～100 cycles/mm、间隔 10，返回子午／弧矢曲线。所有波长参与。

默认每项分析都启动独立 MCP 服务与工作进程，打开本次输入快照；显式有界复用时，一个会话最多运行指定数量的分析。两种模式均在每项分析前后核对公共 `LensData` 暴露的光学字段，绝对容差 `1e-9`、相对容差 `1e-7`，与现有参数回读一致；排除路径、标题、原始列表和警告。精确指纹也保留，容差内相等不要求指纹相同。此检查**不能证明 CODE V 所有未公开内部状态均未改变**。

引擎工作目录放在仓库 `.codev-run/c-<唯一标识>/` 的短 ASCII 路径，输出目录可独立指定。源文件、输出输入快照与内部快照均在结束时重新检查 SHA-256。

`manifest.json` 的 `schema_version=1`，包含：

- 运行状态、来源、时间、代码提交及工作区是否有修改。
- 两份输入原路径、快照相对路径、哈希及结束时的不变性检查。
- 每项请求、实际设置、后端镜头 ID／revision、任务编号、前后状态指纹、警告、耗时。
- 每项产物的包内相对路径、大小、SHA-256；缺失的后端信息保留为空。
- `performance.sessions` 内每个会话的客户端初始化、引擎启动、镜头打开、释放与 COM 调用数；每项分析的计算、导出与回读墙钟耗时。模拟后端不提供真实 COM 数据。

初始／最终目录分别保留输入、分析前后镜头 JSON、状态、任务、原始输出、PNG、真实原生 `.PLT`、MCP 协议日志、stderr 与会话释放记录。MCP 图片内容必须与本地图片逐字节一致，复制后的产物可通过清单哈希复核。模拟原生图没有 `.PLT`，不会伪造。

`comparison.md` 包含数值表和产物链接。点列统计统一用**半径**，分列原生统计与绘图采样数。一阶参数带精度说明；原生图与服务按数值重绘的图分开标识，不宣称其采样一致。WAV 使用保存的当前焦面、全部视场及波长，固定 `NRD=20`；逐视场列出原生 RMS（waves）、Strehl、实际光线数和接受光瞳比（光线数除以视场 1 的光线数；被光阑面和默认孔径挡掉的光线不是追迹失败，也不进 RMS）。初始与最终的接受光瞳比相差超过 3 个百分点时，报告标出“光瞳不同”，并并列不按光线数加权的综合 RMS。镜头参考波长与原生输出未提供的多波长 RMS 等效波长分别标识。视场权重不同且显式放行时，只比较逐视场值，不比较综合值。流程不判定是否达到衍射极限。

## 失败与重跑

分析任务自身失败（`computation_failed`、`unsupported`、`parameter`，或输出被截断）且会话已正常关闭、清理已确认时，该项记为失败并写入清单的 `failed_analyses`（阶段、分析名、错误类型、原因），其余分析照常运行；总体状态为失败、退出码 1，报告与设计记录列出失败项，规格判定中缺失的量为 unknown。任务错配、历史结果、图片不一致、镜头状态改变、会话失效（`session_invalid`／内部错误）、协议或超时故障、释放无法确认，仍使运行在该处停止，保留已生成产物，并以退出码 1 结束。成功退出码为 0。

异步分析到期先尝试取消并保存确认状态；通信失效或同步调用超时则通过关闭客户端和既有服务生命周期释放。取消未确认不会被记录为成功。只关闭本次启动的服务，不按名称终止 CODE V 进程。

重跑始终创建新包，不复用上次成功项，不覆盖旧包。`elapsed_seconds` 是单项编排墙钟时间；复用模式下启动和释放仅计入所在组，阶段耗时另见 `performance`。
